# Threat Model - task

Repo-level. The `task serve` / `remote` part lives in `docs/threat-model-task-serve.md` (T1 to T14); it is not repeated here. Facts cite `CLAUDE.md` sections; "(to validate)" marks an inference not stated in a source. Single-user, developer-machine trust model (confirmed by the owner, 2026-11-14).

## Scope

The `task` CLI, the app-core module `app-module-task`, the storage strategies (`local`, `github`, `gitlab`, `remote` client), the updater and the published packages. Out of scope: attacks on the forges themselves, hostile external plugin code (none is loaded, see P1), supply-chain attacks on npm dependencies (owner decision 2026-11-14: only the owner has access to the GitHub account and publishes; a compromised laptop compromises everything, so it is not a threat task defends against).

## Assets

| Asset                                                                                                          | Sensitivity                                                           |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Task files, `task-index.json`, `config.yml` under `<registry>/projects/<id>/task/`                             | Medium: task text, may hold anything typed                            |
| Forge and server tokens (`GITHUB_TOKEN`, `GITLAB_TOKEN`, `TASK_REMOTE_TOKEN`, `TASK_SERVE_TOKEN`, token files) | High: read/write on the forge project                                 |
| Forge answers cached in `<data>/cache/github/`                                                                 | Medium: private-repo issue content on disk                            |
| Task log (`task cli logs`): resolution lines, `TASK_DEBUG` request lines, event replay text with payload JSON  | Medium: payloads include full task and comment text                   |
| Event payloads sent to queue                                                                                   | Medium: stored by queue (WAL, DLQ, history), see queue's threat model |
| The project registry                                                                                           | High: owned by the `project` CLI                                      |
| The global `~/.task/config.yml` (defaults, hooks)                                                              | Low to medium                                                         |
| Migration journal and lock in the target data folder                                                           | Low                                                                   |
| Published packages, bin shim, platform packages                                                                | High: run on every machine that installs them                         |

## Trust boundaries

- Process to local files: same OS user; the file system permissions are the boundary.
- Task to the registry: read only (P2).
- Task to forges: HTTPS to the configured `baseUrl`; answers are untrusted input.
- Client to `task serve`: see the serve threat model.
- Browser or local process to app-core to the module routes (loopback).
- Task to the queue daemon: through `@wadeck-app/queue-sdk`, which finds and authenticates it.
- Machine to the package registry (GitHub Packages) at update.

| U1  | A malicious or broken package or shim runs on update                           | The shim refuses unsupported platforms before anything else; a non-CalVer (dev) build never updates the global install and spawns no updater; `restore-exec-bits.sh` and `packed-smoke` (macOS arm64 and Linux) run on the packed tarballs before publish; an interrupted `npm install -g` is repaired by the next updater run; test spawns go through `spawnIsolated` (temp config, unreachable registry, own npmrc) so a test never installs for real | Trust in the GitHub Packages scope and the CI publisher; the live-orphan-npm branch of the repair is not verified on Windows; a macOS runner that never starts skips the smoke, publish is blocked only by a real failure | "Updater"                                              |
| D1  | Tasks of a private repo or private data stay on disk after use                 | Cache files live in the project data folder, are expired by every write, and hold no header or token                                                                                                                                                                                                                                                                                                                                                    | Readable by the same OS user; no automatic purge (to validate)                                                                                                                                                            | "Storage strategy: github"                             |
| D2  | A migration copies or overwrites the wrong data                                | Source only read, with fresh reads; same project or two projects on the same location refused; journal and lock (`migrate.lock`, pid); a damaged journal is a loud `MigrationStateError`; read-back compares and reports, never repairs; remote target: events suppressed unless `--emit-events`                                                                                                                                                        |                                                                                                                                                                                                                           | "Migration"                                            |

## Review triggers

Update this file when: an external plugin loader is considered; a hook runner or any command execution is added; the module gains authentication or a new mutating route; a new credential source or strategy lands; the updater or shim changes how it installs; `task serve` changes (then also its own file).
