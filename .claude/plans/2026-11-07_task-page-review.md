# Task page: review of the 10 designs, benchmark, redesign spec

Status: review and spec only, no production code written. Page: `/modules/task/tasks/p/:project/:id`.
Evidence: agent-browser on an isolated app-core-cli `2026.11.6-156-21f5150b` (dsl-ui 318, `--ab-tests`), module packaged with `--version 0.0.0-ui`, sandbox registry (2 projects, 14 tasks). Screenshots: `.claude/screenshots/task-review/01..08` (gitignored). Viewports 1440x900 and 390x800, light and dark (dark looked fine on github-b and linear-a; not reviewed on the others).

Sandbox tasks: a flow-style task (~720-char "title", 5 children, 1 grandchild, parent, 4 labels, 4 metadata keys, blocks 1), a short bug (3 link types), a task blocked by 2 open tasks.

## 1. Facts: title and description

| Fact                                            | Evidence                                                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| A task stores the same string twice             | `task-core/src/TaskStore.ts` `create(title, ...)`: `title`, `description: title`                                                      |
| Nothing edits either field after creation       | `TaskStore` mutators: `setParent removeParent addLink removeLink updateStatus setType addLabel removeLabel setMeta` only              |
| CLI has one text argument                       | `task new <description> [--parent]` (`WriteCommands.ts`, `help.ts`)                                                                   |
| Module has one text field                       | `POST /tasks` body `{description, parent?}` (`taskWriteRoutes.ts`), New task form has one "Description" field                         |
| Index and lists show `title`                    | `TaskSummary.title`; `task list`, tree, tables, history page H1 all print the full text                                               |
| Events carry `description`                      | `onTaskCreated`, `onTaskDeleted` payloads (`queueEventDeclarations.ts`); subscribers may read it                                      |
| Delete filter works on `title`                  | `task delete --filter title=draft*`                                                                                                   |
| No way to remove a metadata key or clear a type | no `removeMeta`, no `clearType` in store, service, CLI, routes                                                                        |
| Page already derives a headline                 | `taskViews.ts` `titleShort` / `hasShortTitle` (`firstSentence`, <= 90 chars) but the Description panel is still shown unconditionally |

Consequence seen: short task = H1 "Fix login redirect loop..." and, in the Description panel right below, the same sentence (screenshot 05). Flow task = ~720-char H1 clamped to 2 lines with "Show more", then the whole text again as Description (02).

### Recommended fix, in two independent steps

| Step                      | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Stored format          | Risk                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | -------------------------- |
| A. Page (no model change) | `headline` = first line/sentence <= 90 chars; `body` = full text; `bodyAddsInfo` = `body.trim() !== headline.trim()`; Description panel and "Show more" only when `bodyAddsInfo`. Same `headline` on history page, list rows, tree, picker                                                                                                                                                                                                                                                                                                                                                                                        | none                   | none                       |
| B. Model                  | `createTask(ctx, {title, description?})`: `description` stored only when it differs from `title`; readers use `description ?? title` so old files (title === description) and events stay valid. CLI `task new "<title>" [--description <text> \| --description-file <path>]` (stdin `-`), `task set-title <id> <text>`, `task set-description <id> <text>`. Module `POST /tasks {title?, description}` (`description` alone keeps working), `PATCH /tasks/:id {title?, description?}`. Index `title` is rewritten on `set-title`. New event `onTaskTextChanged {taskId, field, oldValue?, newValue}` (declaration + hash change) | additive, optional key | owner decision D1/D2 below |

Step A alone removes the duplication for every existing task. Step B is needed for editing and for `task new "short" --description "long"`.

## 4. Redesign: three designs, delete the other eight

Rule for all three (single source of truth per fact):

| Fact     | Shown once in                                                                                                  | Editable there                                 |
| -------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Id       | header, mono, copy on click (the shell crumb is the only other place and is not ours)                          | no                                             |
| Headline | header H1, one line, tooltip with full text                                                                    | yes (after step B)                             |
| Body     | body panel, only when `bodyAddsInfo`                                                                           | yes (after step B)                             |
| Status   | status pill (design 1/2) or stepper (design 3)                                                                 | yes, on pick                                   |
| Type     | property pill/row                                                                                              | yes, with a "none" choice                      |
| Project  | not repeated (the crumb carries it; shown only in cross-project contexts)                                      | no                                             |
| Parent   | property row/pill "Parent" (chain as breadcrumb above the header only if depth >= 2, replacing the row's text) | yes, picker                                    |
| Children | sub-tasks section with progress; header has "Add sub-task"                                                     | rows editable                                  |
| Links    | relations section grouped by relation; "Blocked by N open" banner lives only in the header when N > 0          | yes, picker                                    |
| Dates    | one muted line in the activity header: "Created X, updated Y" with exact time as tooltip                       | no                                             |
| Metadata | properties list at the bottom, collapsed beyond 3 keys                                                         | click value to edit, x to remove (needs route) |
| Activity | one timeline: created + status moves (history has nothing else)                                                | no                                             |

### Design 1 "Issue" (document first; GitHub + GitLab + Jira). Base: github-b

- Header: breadcrumb of ancestors (only if parent exists), `id` mono + headline H1 (1 line), status pill (select on click), overflow menu `...` (History, Copy id, Delete). No Delete button in the toolbar.
- Main column: progress strip (only with children), body (Markdown, "Show more" past 12 lines, edit pencil after step B), Sub-tasks table with inline add row (title, Enter), Relations grouped (each row id + title + status, x), Activity (collapsed after 3 rows).
- Side column (sticky, 20 rem): Status, Type, Labels, Parent, Metadata, Dates. Each row = label + value + click opens its picker popover (no permanent forms).
- Narrow (<900 px): side column moves ABOVE the main column as the pill row of design 2 (today it falls below Activity).
- Option row: `Activity` (timeline / tab). Nothing else.

### Design 2 "Bar" (properties as pills; Linear). Base: linear-a

- Header: id + headline (1 line, wraps to 2 on mobile), then ONE pill row: status | type | labels (chips + "+") | parent | "Blocked by 2" (danger pill, only if > 0). Every pill has a text label inside ("Parent: Q4 platform...", "Type: feature") so none is anonymous (fixes the unlabeled parent chip).
- Pills open popovers: status (list of statuses with tone dot), type (list + "None"), labels (combobox), parent (task picker + "Detach"), links (relation select + picker), metadata (key/value editor).
- Body: Markdown, then sub-tasks, relations (rows with x), activity collapsed. One column, max width 56 rem.
- Option row: `Pills` (all / only set ones).

### Design 3 "Flow" (workflow monitoring; Jira transitions + checklist)

For tasks produced by flows (prompt as text, children as steps, status as pipeline).

- Header: id + headline, then a status stepper (`task:SegmentedControl`, exists): all statuses in config order, terminal ones separated by a divider, one click moves; a "Blocked by N open" banner with links when blocked.
- Body collapsed to 6 lines with "Show more" (prompt-like text is long).
- Steps checklist: children as rows with a checkbox that toggles terminal/default status, inline status select per row, progress ring; "Add step" row.
- Right of the checklist (or below on narrow): compact properties (type, labels, parent, metadata).
- Activity timeline directly under the steps, expanded.
- Option row: `Body` (collapsed / expanded).

### Implications for WP4 / WP5

- New components may call `ctx.onAction(name, params, { body })`: values can travel in a JSON body, so the "value in the path" routes (`/status/:status`, `/labels/:label`) are no longer required for them; labels containing `/` and metadata values become possible with a body route. `resultKey` badges work through `ctx.onAction`, so `pageActionHandler` (`dsl-lib-task/src/compat/actions.ts`) is unnecessary on 318. 094/175 remain the baseline in CLAUDE.md: decide the minimum shell before dropping it.
- Build `TaskPicker` (fetch + abort + listbox, pattern verified), `LabelCombobox` (needs a "Create" row and counts; `FieldAutocomplete` cannot create and drops free text), `PropertyPopover` (closing after `await onAction` works; YAML `Popover` cannot close itself), `MetaEditor`. Pass the project as a prop (`$route.project`, resolved with `resolveExpressionValue`).
- Built-ins to use: `Dialog` with `trigger` (delete consequences; the text must come from a source, not from a fetch on open), `ConfirmDialog` opened through a `$vars` key set by a component, `ActionButton` with `body`, `FieldAutocomplete` for closed lists only (statuses, types, relation) with `{value,label}` options, `FieldTags` only if suggestion-less free tags are acceptable.
- Do not use: `FieldAsyncSelect`; YAML `ContextMenu` for actions (the overflow menu is a custom component or a `Popover` of `ButtonLink` / `ActionButton`); YAML `Popover` where it must close after success.
- Forms are not reset on 318: components that add items (label, sub-task title, link target) clear their own input after `await onAction`.
- Search through `$sources` is possible only via `$urlParam` (every debounced keystroke rewrites the URL and refetches the page sources naming it), so `fetch` stays the choice for pickers.

- `setSearchParams` with `replace: true` and browser Back were not tested; `app-core-cli serve` (instead of `dev`) was not used.
