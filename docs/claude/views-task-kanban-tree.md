## Task page (one design, A/B rows baked)

`/tasks/p/:project/:id` is ONE design merged from the GitHub, Jira and GitLab layouts (user feedback; the three product views are deleted). Its seven localized A/B rows were baked on 2026-11-14: nobody picked another option, so the first one of each is the only implementation (`AbTest` nodes, losing fragments, their component props and tests are deleted; the generated view differs from the former production page only by the removed `AbTest` wrappers). Source and generator: see Source below.

Base layout: title (`InlineText`); header line = Open / Closed `StatusBadge` (tone of the status: red for a negative close), id, "Opened <date>", and on the right a direct `Delete` button (`task:ControlButton`, danger, `Dialog` trigger, 32 px; never a menu for one action); main column = Description, Sub-tasks, Relations, Activity; sticky right sidebar with NO card or background: first line the Type pill then the Status pill (no labels; type left; a project without types shows a compact free-text type field in the same line), a `Divider`, then a divided `PropertyList` of inline rows (label left, value right): Parent, Labels (chips with x and "+ Add"), Metadata (same), Updated. No "No labels" / "No metadata" empty text. No word "terminal" in any text: the green / red colour of the pill and of the dots in the list says how a status ended (`outcome: negative` gives tone `danger`). The sidebar stacks above the main column below 1024 px. NO `task:project-header` slot on this page (a "Project" link at the top is forbidden: the breadcrumb carries it); it stays on the list and tree pages.

Main column blocks (`variants/_sections.yaml`): Description = `task:Panel` `appearance: strip`; Sub-tasks = checklist whose add field is the last row (plus icon), progress bar; Relations = groups built by the route (`links.groups`) then the add row (relation select with icon + search on one line) as the last row of the panel; Activity = plain panel with `ActivityFeed` tabs All / Comments / History, composer above the tabs.

- Sub-task rows have a detach icon button (tooltip "Detach from parent"): action `detachChild` = `DELETE /tasks/{childId}/parent`, result key `detachResult` (Notice + undelivered Notice in `feedback.all`). The placeholder is `{childId}`, NOT `{id}`: measured in the shell, a body-less action fills `{id}` from the page, so the first version detached the page's own task. The backend writes `parent` on the child and `child-removed` / `child-added` on the parent; `ActivityFeed` draws them (git-branch, neutral, History filter).
- New dsl-lib pieces: `ControlButton`, `ui/icons.ts` (closed icon list, relation icons), `TaskChecklist` (`detachAction`, `detachIdParam`), `TaskPicker` (`layout: row`), `PropertyPopover.icon` (no page uses it since the baking; kept) (an action trigger: icon, no chevron), `PropertyList.dividers` (rows carry `py-2`, no gap), `TaskRowList` meta as a pill.
- Source: `src/dsl-views/variants/`: `_page.yaml` (verbatim head with `$sources`/`$actions`, then `$notices`, the base `$view`, `$page`), `_shared.yaml` (facts and editors), `_sections.yaml` (the four blocks of the main column); fragments are used as `{ $use: name }` anywhere. `task-page.yaml` is GENERATED (`npm run views --workspace=packages/app-module-task`, freshness-tested); the view is wrapped in `$if: $sources.detail.task`, the notices stay outside. Tests (`taskPageVariants.test.ts`): invariants on the single page, plus one test per baked block and a check that no `AbTest` is left. A new A/B row: add an `AbTest` node in a fragment (the generator no longer checks that repeated declarations match: keep them identical, the shell dock reports a conflict) and extend the test, which forbids `AbTest` today.

- Activity block: ONE `task:ActivityFeed` per design (`rows: $sources.activity.rows`, `filters` all / comments / history, counts in the tabs computed from the rows). Its slots take LISTS of nodes: `commentsContent` holds the `CommentThread` (shown in the Comments filter instead of the comment rows) and `composer` the `CommentComposer` (always shown, above the tabs). A single object in a slot draws nothing (found in the browser). The Open / Closed badge shows the STATE (`isOpen` / `isTerminal` of the detail), not the status, which is edited by the StatusSelect only.
- Components added for this: `ActivityFeed` (kind normalisation of the real row kinds, `oldValue` / `newValue` details, `commentsContent`, `composer`, `defaultFilter`), `TaskChecklist.progress` (ring, bar, none), `PropertyPopover` (`appearance` field and button, `actionLabel`, `align`), `StatusSelect.appearance`, `Panel` appearance `strip`, `PropertyRow.align` (control), `Caption`. `useDismiss` ignores what happens inside a `role="dialog"` (a dialog opened from a popover closed its popover, and itself, as it opened).
- Single source of truth: each fact (id, headline, status, type, parent, labels, dates, sub-tasks, metadata, activity) is bound by ONE node per design, where it is edited (`taskPageVariants.test.ts` counts the bindings; the project and `task.title` are never bound). The id is a `Badge`, the title the headline (<= 90 chars) in an `InlineText`; the body (`body`, `InlineText` multiline) shows only when `bodyAddsInfo`, else "Add a description" (`noBodyInfo`).
- Controls (dsl-ui >= 318: `onAction(name, params, { body })` sends a JSON body): `PropertyPopover` (type with "None" = `POST /type {type: ''}`, parent), `StatusSelect` (status), `TaskPicker` (parent: `excludeDescendantsOf`; link: `choices` = relation select, body `{type, target}`), `LabelCombobox`, `MetaEditor` (`removeMetaKey` by base64url key), `TaskChecklist` (`createSubtask`, `setChildStatus`; statuses `terminalStatus` / `reopenStatus` from the config), `InlineText` (`setText` = `PATCH /tasks/:id`). Delete: the "Actions" `PropertyPopover` holds a `Dialog` (consequences `deleteImpactText`, cascade `Switch` only with descendants, `forms.delete` posts `{ids, cascade, confirm: true}`); the answer is read by the page-level notices because the task is gone afterwards.
- Feedback: one block `feedback.all` per design (error + `undeliveredText` as `task:Notice` for each of `status|type|label|meta|parent|link|linkRow|text|subtask|comment`Result), placed so it does not push the controls down (main column). With the queue unreachable (`QUEUE_SDK_OFF`) every first change adds a tall notice: expected there.
- Tabs (manifest `tab`, app-core-cli >= 2026.11.7-171): one group `project` = Tasks / Tree / Types (the former `task` group Details / History is gone: a group needs two pages and the Activity block replaced History); none on the task, new or delete pages. The pages carry no History, Tasks, Tree or Children link (`Open parent` is the one link left, inside the Parent picker). `lockfile` pins app-core-cli and app-core-sdk 2026.11.7-171-cb12178d, `package.json` keeps `latest`; this SDK adds `fileVersion` / `unchanged` to `ModuleContext` (test contexts provide them).
- Data: presentation fields of `GET /tasks/:id` are listed at the top of `taskViews.ts` (`headline`, `body`, `bodyAddsInfo`, `noBodyInfo`, `statusOptions`, `typeOptions`, `metaEntries`, `checklistRows`, `terminalStatus`, `reopenStatus`, `pills`, `pillTexts`, `deleteImpact*`, `forms.delete`); the temporary `titleShort` / `hasShortTitle` are removed. `GET /projects?ids=` fills `forms.delete.ids` (the delete page source passes `$urlParam.ids`).
- Test against a real shell: package to a temp folder, `app-core-cli dev <tmp> --port <free> --no-tray` from a temp prefix install of the pinned CLI (`--watch` needs a source module and writes into the repo: not used); a new package needs a restart.
- Verified in a browser (app-core-cli 2026.11.7-171, dsl-ui 318, 1440 and 390 px, light and dark): status, type (and clear), labels (suggestion, new, remove), title, body, metadata (edit, add, remove, key with "/"), parent (search, descendants not offered, detach), link add/remove, sub-task add/tick, delete dialog with cascade, project tabs, empty console (previous designs).

## Kanban board (5 variants, live)

`/tasks/p/:project/board` (tab "Board" of the `project` group) and, inside the project module, a "Board" `Section` contributed to `project:project-panels` (`optionalRequires: {project}`, widget `src/dsl-views/project-board-panel.yaml`; nothing is edited in the project repo; an absent project module drops the contribution). Plan and facts: `.claude/plans/2026-11-14_kanban-board.md`.

- Data: `GET /tasks/board?project=` (`boardRoutes.ts`, `boardView.ts`): columns in config order (`listStatuses`), cards from ONE list read (id, headline, href, effective priority, assignee, tone, `createdAt`; no type/labels: the summaries do not carry them), at most 100 cards per column (`hiddenCount`), `version` (hash of statuses config + id/status/title/priority/assignee), `warning` for tasks in a status the config does not list, `abSwitcher`. A move is the existing `POST /tasks/:id/status`: same events and `undeliveredText` as every status change.
- Live: no push bus exists in the shell, so the module serves its own SSE `GET /board/events?project=` (`boardEvents.ts`; event `version`, heartbeat 20 s, retry 5 s; one 2 s timer per stream, closed on disconnect and teardown). Local strategy: stat of `task-index.json` every 2 s plus a forced read every 30 s; github/gitlab/remote: a list read every 30 s; writes of the module itself notify at once. The component refetches when the version changes; without the stream it polls every `pollSeconds` (20 s). Chip: Live / Reconnecting / Polling. Verified in a real shell: a CLI `set-status` moved the card in under 4 s.
- Component `task:KanbanBoard` (`dsl-lib-task`, native HTML5 drag, no dependency): variants `columns`, `swimlanes`, `compact`, `rails`, `tabs` (no drag; every card also has a keyboard "Move to" menu). Page mode (`moveAction: moveCard`, param `cardId`, answer shown by the page notices) and contribution mode (no `columns`, no `moveAction`: it fetches the board and POSTs `movePath` itself, shows a `role=alert` message with Dismiss). `projectParam` is always the raw reference (encoded once by the component).
- A/B switcher: large floating bar, bottom center, wraps at 390 px, choice in `localStorage` `task.kanban.variant`; only when the module process runs with `TASK_KANBAN_AB=1` (dev); absent otherwise (verified). The winner is baked later like the task page: delete the others and the switcher.
- Verified in a real shell (app-core-cli 2026.11.8-179, 1440 and 390 px, light and dark): all variants, drag in columns, swimlanes, compact, rails (rail drop with a real mouse sequence; `agent-browser drag` did nothing on a rail button, tool limit not proven), embed drag, refused move in both modes, switcher absent without the variable, polling state with the stream blocked. Known: the shell shows its own green "Done" toast on a refused move (`inlineErrors` answers 200); in the embed the switcher can cover a card; the stored variant is shared by the page and the embed (same `localStorage` key).
- Not done: card type, labels and `updatedAt` (needs per-task reads); terminal columns are ordered newest-created first; no WIP limits; no board across projects.

## Tree page (global, several projects)

`/tree` without `?project` renders `task:ProjectAccordion` over `projects` of `GET /tree?allProjects=true` (hand-written `tree-page.yaml`; per project `/tree/p/:project` and the single-project case are the table). It won a 5-design A/B test (master-detail, picker, cards, flat list lost and were deleted); history and measures: `.claude/plans/2026-11-06_tree-variants.md`.

- `projects` (`treeProjects.ts`): every project sorted by name; readable ones carry `open`, `total`, `percent`, `empty`, `allDone`, `summaryText`, `rows` (depth first, at most `ROW_CAP` = 60: `id`, `title`, `titleText`, `status`, `tone`, `depth`, `href`), `hiddenCount` / `moreText` (link to the project's tree), `treeHref`; unreadable ones `readable: false` + `problemText` (reason and fix). No `?rowCap`, no `groups`, no `overview`.
- Nothing is open at first load except the project opened last time (`localStorage` `task.tree.accordion.last`, set when a project is opened; unknown id = nothing open). Why: dozens of projects must start as a compact index, and "the first project" is arbitrary; "Expand all" opens every project shown that has rows.
- Empty project: one plain "No tasks" line, no toggle. Unreadable project: flagged line ("cannot be read"), its body gives the reason and fix (`whitespace-pre-wrap`, the YAML code frame stays readable).
- `warning` is ONE line (`unreadableSummary`: count, up to 5 names, "Open one in the list below for its reason and fix."), never paths or YAML errors; `skipped` / `skippedCount` in the answer are unchanged.
- Measured (sandbox: 31 projects, 698 tasks, 2 unreadable, one project of 300 tasks at depth 8, 127.0.0.1, warm): route 20 ms and 89 KB, was 26 ms and 231 KB with `groups`. `localhost` adds about 200 ms per request on this machine (IPv6 fallback): measure on 127.0.0.1. Browser-checked at 1440 and 390 px, dark and light, filter, expand all, flagged rows, one project, empty registry.
- Not done: no "last added" sort (the index has no `updatedAt`); expanding all shows up to 60 rows per project (no virtualisation).
